AI Coach: Great question. Creating a new database connection is expensive — it requires a network handshake, authentication, and resource allocation on both the client and server side. That can take 50-100ms or more each time.

A connection pool maintains a set of reusable connections that stay open. When your code needs to run a query, it borrows a connection from the pool, executes the query, and returns the connection for reuse. This is much faster — often under 1ms to get a connection from the pool.

In a web application where you might handle hundreds of requests per second, creating a new connection for each request would be a massive bottleneck. The pool also limits the total number of connections to your database, preventing you from overwhelming it.

So the rule is: almost always use a connection pool in production applications. The only time you might create individual connections is for one-off scripts or admin tasks.
